# 背景与目标

当前BeTrust质押业务已具备借款、还款、计息、风控计算（预警/强平质押率）能力，本文档描述强平触发后的执行环节，解决三个核心问题：

1. 信号触发：BeTrust风控系统判定某借款订单达到强平条件后，如何把"需要清仓"这件事，以结构化、可追溯、防重复的方式传递给执行方（即mojo）

2. 信号执行：执行方（清算执行引擎）收到信号后，如何拆单、选择交易所/账户、下单、监控成交、处理异常

3. 结果回传：执行完成（或中途异常）后，如何把卖出结果、清算回款、账务抵扣结果传回借贷平台，驱动订单状态和账务状态收口

**设计原则：**

- 借款订单ID → 强平编号 → 卖出批次号 → 平台子订单号/交易所订单号 → 成交编号，全链路编号串联

- 所有原始回报必须留痕

- 交易所成交回报按成交编号幂等入库；强平任务按强平编号幂等触发，不得重复发起

- 强平完成后，借款订单状态、强平状态、卖出批次状态、账务结算状态必须最终一致

## 3\.3 接口设计

### 3\.3\.1 请求接口

**接口名称**：`POST /liquidation/tasks`（触发清算任务）

**请求字段：**

|字段|类型|说明|
|---|---|---|
|liquidation\_id|string|强平编号，由BeTrust系统生成，全局唯一，Mojo进行幂等检验，防止重复触发|
|loan\_order\_id|string|借款订单ID|
|uid|string|被强平用户ID|
|original\_ratio|decimal|初始质押率|
|trigger\_ratio|decimal|触发时的质押率快照|
|trigger\_mark\_price|decimal|触发标记价格快照|
|~~target\_ratio~~|~~decimal~~|~~要求强平后希望达到的质押率~~|
|collateral\_asset|string|抵押币种|
|collateral\_amount|decimal|现时抵押数量快照|
|total\_due|decimal|强平前应还总额，即用户负债总额|



### 3\.3\.2 取消接口

清算执行期间用户随时可能补充抵押物或提前还款，此时继续卖出就是在处置用户本不该被处置的资产。

**取消 = 停止后续卖出，不等于撤销已成交部分。** 

**接口名称**：`POST /liquidation/tasks/{liquidation_id}/cancel`

|字段|类型|说明|
|---|---|---|
|liquidation\_id|string|要取消的强平编号，同时作为幂等键|
|cancel\_reason|enum|用户补充抵押物 / 用户提前还款 / 人工干预 / 其他|
|requested\_at|datetime（毫秒）|平台发起取消的时间|

**同步响应**

|字段|说明|
|---|---|
|cancel\_result|`accepted`（已受理，停止后续卖出）/ `already_finished`（任务已终态，无法取消）/ `rejected`（附原因）|
|filled\_amount\_at\_cancel|受理取消时该任务的累计已成交数量快照|
|net\_proceeds\_at\_cancel|受理取消时的累计净回款快照|



### 3\.3\.3 状态查询接口

回调可能因网络、平台侧故障而丢失。平台需要一个主动查询通道，避免任务状态长期悬空。

**接口名称**：`GET /liquidation/tasks`（Query：`liquidation_id`、`timestamp`、`sign`）

返回该任务的当前状态、累计已成交数量、累计净回款、当前所处档位、已生成的卖出批次列表，以及若已终态则返回完整结算结果。

该接口为只读，不产生任何执行动作，可安全重复调用。建议平台对超过预期时长仍未收到终态回调的任务定时轮询。

- 路由：

    - 选择交易所：TBC，根据币对流动性和路由配置选择交易所

    - 选择执行账户：TBC，待确认BeTrust是否有多个质押账户



## 4\.2 处置数量计算

### 4\.2\.1 安全缓冲

当同一时间有多笔强平请求时，按`安全缓冲`决定执行优先级。

破产价 = total\_due ÷ collateral\_amount

安全缓冲 = \(当前现货价 − 破产价\) ÷ 当前现货价



### 4\.2\.2 处置数量

计算此笔强平请求预估需要卖出多少抵押物：

~~卖出数量 = \(total\_due − target\_ratio × collateral\_amount × trigger\_mark\_price\) ÷ \(trigger\_mark\_price × \(1 − target\_ratio\)\)~~

x = D ÷ \(P × \(1 − f\)\)

`D` = 当前负债合计（即 `total_due`）

`P` = 触发指数价（即`trigger_mark_price`）

`f` = 交易所手续费率（Binance默认按0\.1%计算。https://www\.binance\.com/zh\-CN/fee/trading）

**卖出数量 = min\(x, collateral\_amount\)**



## 4\.3 执行策略

### 4\.3\.1 决定通道

同一币对、同一时间窗口内：

IF 所有在途清算任务的卖出总量 ≤ 该币对当前买盘深度 × 全局上限比例（默认30%）THEN  继续执行强平策略

ELSE  先在永续合约开等量空单把价格风险锁住，再从容在现货分批卖出，卖多少平多少空  OR  走场外OTC/大宗\<\- TBC



### 4\.3\.2 核心原则

1. 所有卖单都走 IOC 可成交限价单，即能成交的立即成交，未成交部分自动撤销。

2. 每次下单前重新读取最新盘口

3. 实际成交价格突破硬边界时停止挂单转异常处理，不无底线降价。



### 4\.3\.4 价格保护

计算每笔子订单的卖出底价：

盘口保护价 = 买一价×\(1−当前档位盘口偏移\)

指数价，多所加权，不依赖单一交易所  \<\- TBC



每笔子订单按照进入条件决定档位：

|档位|进入条件|盘口偏移|报价间隔|目标|
|---|---|---|---|---|
|P0|安全缓冲 \< 8%，或执行总时间超30秒|BTC 1\.50% / ETH 2\.00%|0\.5秒|紧急，尽快完成|
|P1|安全缓冲 8%\-15%，或执行总时间超15秒，或连续3次IOC未成交，或近5秒价格跌幅\>0\.5%|0\.80%<br>|1秒|优先缩短暴露时间|
|P2|安全缓冲 \> 15%，且执行总时间 \< 15秒|0\.30%|1秒|正常执行|

档位只向更紧急方向切换，不回退。



### 4\.3\.5 每个报价间隔动作序列

1. 读取本所最新盘口 \+ 各成分所指数价

2. 重算安全缓冲（4\.2\.1）

3. 按当前档位参数算盘口保护价、指数价保护价，取 MAX 得本轮最低卖价

4. 统计本轮最低卖价以上的有效买盘深度

5. （第一次执行此序列时）计算此笔强平订单的处置数量（4\.2\.2）

6. （第二次执行或以后）计算还需卖多少:
累计项均限定 WHERE liquidation\_id = 本任务（跨此任务全部批次）：  
剩余负债   = 触发快照负债 D   − 累计实际净回款 
剩余抵押物 = 触发快照抵押数量 C − 累计已成交数量  
还需卖出量 = min\{剩余负债 ÷ \(当前现货价 × \(1 − 手续费率\)\), 剩余抵押物\}

7. 取min\(本轮最低卖价以上的有效买盘深度×20%, 还需卖出量\)

8. 按 tickSize 向上取整价格、stepSize 向下取整数量

9. 发送一笔 IOC 卖单（数量取步骤5/6结果，限价取步骤3的本轮最低卖价）

10. 接收成交回报，更新累计成交、还需卖出量

11. 终止判定（详见 4\.4\.2）：负债清零 / 抵押物耗尽 / 继续。前二者立即结束执行，最后一种回到步骤1



### 4\.3\.6 委托受理与成交监控

- 提交后立即记录交易所订单号，并轮询/订阅交易所回报更新：成交数量、未成交数量、成交均价、订单状态

- 逐笔成交回报，按成交编号幂等入库

- 完整保存交易所原始回报，用于对账和追溯



## 4\.4 完成判定与循环处理

### 4\.4\.1 单笔强平交易所订单终态

- 当"未成交数量"归零，标记该子订单"已完成"

- 若子订单被交易所拒绝、超时或部分成交后停止（如流动性不足），保留已成交部分，剩余部分并入下一轮重新计算。



### 4\.4\.2 达标复核

每个报价间隔，按照`liquidation_id`进行聚合，用当前实际成交结果重新计算质押率。

1. 用实际成交结果重算：
累计净回款   = Σ 成交金额 − Σ 手续费
累计成交数量 = Σ 成交数量
剩余负债   = 触发快照负债 D   − 累计净回款
剩余抵押物 = 触发快照抵押数量 C − 累计成交数量
~~复核质押率 = 剩余负债 ÷ \(剩余抵押物 × ~~~~当前中间价~~~~\)~~

2. 判定分支，按顺序检查：

    1. 剩余负债 ≤ 0：**已清偿（成功终态）**：停止发单，以 `settled` 终态回调

    2. 剩余抵押物 ≤ 交易所最小委托数量，且剩余负债 \> 0：**抵押物耗尽**：停止发单，以 `bad_debt` 终态回调并触发告警

    3. ~~复核质押率 ≤ 目标质押率：~~**~~达标~~**~~，本次强平完成，进入 5\.1 结果归集~~

    4. ~~复核质押率 \> 目标质押率，且仍有剩余抵押物：~~**~~未达标~~**~~，继续按 4\.2 发起下一轮：以剩余负债、剩余抵押物、当前指数价重新代入 4\.2 公式，产生新的卖出批次（沿用同一强平编号）~~

    5. 以上均不满足：继续循环第1步



## 4\.5 异常处理

|场景|处理|
|---|---|
|交易所接口超时，结果未知|保持"处理中"，不重复委托，告警人工调查；<br>确认原委托失败/已撤销方可重新下单|
|交易所返回失败代码|记录"失败代码"与"失败原因"，触发重新下单|
|连续N次下单失败（默认3次）|暂停该任务新订单，触发强通知转人工|
|行情超过阈值未更新（默认3秒）|暂停新订单，行情恢复后从剩余数量继续|
|可用余额不足|告警，停止下单，核对账户余额和已成交数量，转人工|



# 功能三：执行结果回传平台

## 5\.1 结果归集

清算执行引擎在判定卖出流程结束后，对本次强平编号下的全部成交明细做汇总：

实际卖出抵押物 = Σ 成交数量

成交总额       = Σ 成交金额

交易所手续费   = Σ 手续费

实际清算回款   = 成交总额 − 交易所手续费

# 内部告警

1. 同一币对同一时刻在途清算任务数 \> N（默认3）   或 同一币对在途清算任务的名义金额合计 \> M（默认50万美元）或单一卖出订单执行时长超过5分钟  或 单一卖出订单执行次数超过5次

2. 当有任何一单成交价（明细，非整单平均成交价）小于等于硬边界时，告警。
硬边界：
BTC最低允许价格 = 中间价 × \(1 − 2\.00%\) 
ETH最低允许价格 = 中间价 × \(1 − 2\.50%\)

3. 发生坏账时：剩余抵押物已耗尽但剩余负债 \> 0

4. 账户可用余额/抵押物不足：下单失败
